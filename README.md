# ai flow and game structure

why working with AI workflows is similar to games, and why script languages and machines are the future

is games of friends and foes - AI working strategy?
 
## games and AI flows

- both are a loop: read state, pick a move, apply rules, new state
- the model is the player, the runtime is the engine, tools are the legal moves
- the player sends intent, the engine validates and applies it

## languages as validated structure

- a language is a set of shapes known to be valid, the model fills them
- generated scripts are checked statically before execution
- values are checked before they are used
- the execution flow validates itself, every path taken was accepted by the checker
- only checked programs run and process AI data

## the container

- language plus machine is a container for AI to work with tools
- outside it the model can only talk, inside it the model can act

## paradise, power and love

- paradise: the container that can create everything, the interpreter and its modules
- power: what protects it, static checks, authority and the sandbox and what it takes
- love: what binds it
  - a burst: one brilliant answer that fades
  - a structure that lasts: a checked script that runs and replays the same way


games simulate the lasting kind on rules, inside the rules play is free

## conclusion

- build AI flows like games: a small script language on a strict machine
